# ИИ-агент исполнительной документации

Локальный MVP: загрузка исходных файлов, анализ OpenAI Responses API, `NEEDS_INPUT`, заполнение АОСР КЛ-0,4 кВ / КЛ-6 кВ / ВРЩ, проверка и итоговый ZIP.

Модель определяет состав работ, сопоставляет источники и строит семантический план. Python ограниченно читает файлы, патчит только разрешённые ячейки OOXML, рендерит PDF, выполняет проверки и собирает архив. Критичные значения без источника не допускаются.

## Запуск

```bash
cp .env.example .env
# заполнить OPENAI_API_KEY и при необходимости OPENAI_MODEL
uv sync --extra dev
uv run uvicorn --app-dir src executive_docs.main:app --host 127.0.0.1 --port 8000
```

Открыть `http://127.0.0.1:8000`.

Требуются Python 3.12 и LibreOffice (`soffice`). Путь к LibreOffice можно задать через `SOFFICE_PATH`.

Для локальной проверки без API установить `AGENT_MODE=heuristic`. Этот режим проверяет flow и `NEEDS_INPUT`, но не заменяет модельный анализ проекта.

Эвристический режим намеренно не может перейти в `READY_FOR_REVIEW`: независимая модельная проверка обязательна. Он нужен для проверки загрузки, очереди, вопросов, генератора и валидаторов без расхода API.

## Реальный тест project1

1. Утвердить очищенные пилотные шаблоны и профили филиалов.
2. Запустить приложение с `AGENT_MODE=openai` и рабочим `OPENAI_API_KEY`.
3. Создать задание «Химки» и указать первый номер АОСР.
4. Загрузить основной PDF проекта и PDF исполнительных схем из `project1/`.
5. Не загружать три заполненных XLSX: они остаются материалом для слепого сравнения.
6. Первый проход должен вернуть `NEEDS_INPUT` по фактическим датам, паспортам/сертификатам, изменениям и неутверждённому профилю.
7. Передать только подтверждённые сведения. После генерации изучить PDF и отчёт проверок.
8. Сравнить результат с экспертно очищенным golden set. Только специалист нажимает подтверждение финального комплекта.

Задания и их ревизии находятся в `data/runs/<job-id>/`. Предыдущая ревизия не перезаписывается.

Быстрая подготовка слепого задания без API и без заполненных Excel:

```bash
uv run python scripts/run_project1_blind.py --mode heuristic --branch khimki --first-number 1
```

Команда печатает `job_id`; запустите веб-приложение и откройте это задание из списка. Для настоящего анализа используйте `--mode openai` после настройки ключа.

## Подготовка шаблонов

```bash
uv run python scripts/qualify_templates.py
```

Команда создаёт отчёт о дефектах и контрольные суммы, не меняя исходные файлы. Найденные `#REF!`, внешние ссылки и старые данные не исправляются автоматически.

После ручной очистки и проверки специалист регистрирует конкретный файл:

```bash
uv run python scripts/approve_template.py \
  --template-id aosr_kl_6 \
  --clean-file /путь/к/очищенному.xlsx \
  --version 1.0 \
  --approved-by "ФИО" \
  --notes "Проверены формулы, печать и старые значения"
```

До этого контракт имеет `approved: false`, а выпуск закономерно завершится `FAILED_VALIDATION` с кодом `TEMPLATE_NOT_APPROVED`.

Текущий отчёт квалификации: `templates/qualification-report.json`. Он фиксирует ошибки формул и именованных диапазонов в шаблоне КЛ, а также формульные ошибки и внешние ссылки в шаблоне ВРЩ.

## Профили организации и филиалов

Файлы `profiles/organization.yaml`, `profiles/khimki.yaml` и `profiles/solnechnogorsk.yaml` заполнены найденными кандидатами, но имеют `approved: false`. Значения из старых книг не используются автоматически. Специалист проверяет реквизиты, ФИО, должности, приказы и периоды полномочий, заполняет пропуски, затем выполняет:

```bash
uv run python scripts/approve_profile.py \
  --profile solnechnogorsk \
  --version 1.0 \
  --approved-by "ФИО" \
  --effective-from 2026-01-01 \
  --effective-to 2026-12-31
```

Организация утверждается такой же командой с `--profile organization`. Профиль вне периода фактических работ блокирует выпуск.

## Состояния и API

Основной путь: `FILES_UPLOADED → ANALYZING ↔ NEEDS_INPUT → GENERATING → VALIDATING → READY_FOR_REVIEW → APPROVED_FINAL`.

- `POST /api/jobs` — multipart-загрузка;
- `GET /api/jobs/{id}` — состояние и доказательства;
- `POST /api/jobs/{id}/answers` — подтверждённые ответы;
- `GET /api/jobs/{id}/preview` — PDF текущей ревизии;
- `POST /api/jobs/{id}/review` — подтверждение, исправление или отмена;
- `GET /api/jobs/{id}/download` — только утверждённый ZIP;
- `GET /api/corrections` — предложения для базы знаний;
- `POST /api/corrections/{id}/review` — ручное решение по предложению.

Customer/global-исправление нельзя утвердить без подтверждённого регрессионного прогона. Утверждение proposal не меняет скилл автоматически.

## Безопасность MVP

Приложение запускается только на `127.0.0.1` и не содержит авторизации. Не публикуйте его на `0.0.0.0`. Исходники не изменяются; имена вложений нормализуются; Office-файлы проверяются как OOXML и ограничиваются по распакованному размеру. Текст внутри загруженных документов всегда считается данными, а не инструкциями агенту. В режиме `openai` выбранные исходники и PDF-превью передаются в OpenAI API; временные File API-объекты удаляются после вызова, а Responses создаются с `store=false`.
